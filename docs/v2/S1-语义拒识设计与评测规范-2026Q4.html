1. 问题定义

1.1 S1 在 S0–S4 中的位置

沿用项目场景表（v2 定稿 §1 与之对齐）：

编号场景说话人交流对象系统动作
S0真实指令主用户设备响应
S1主用户转向他人主用户旁人静默（本篇）
S2旁人对主用户旁人主用户静默
S3旁人之间旁人旁人静默
S4媒体/电子人声电子源—静默

S1 在学术侧的对应名是 SDO（Speech Directed at Others），FDB v1.5 里叫 talking to others，2001 年 EUROSPEECH 叫 Off-Talk。v2 定稿 §1.3 已核过这些术语的判定层级差异 [已核]。

1.2 S1 为什么最难：四类信号同时失效

信号在 S2/S3 是否有效在 S1原因
声纹 / 说话人身份✅ 主判据❌说话人还是同一个主用户
音区 / 距离 / DoA✅ 有效❌同一位置、同一通道；侧头只是弱线索且不等于受话对象
能量 / 音量 / 信噪比✅ 有效❌无系统性差异
文本关键词 / 意图槽位⚠️ 部分❌「把空调关了」对副驾说时，文本与 S0 完全同形
语用连贯性 / 对话状态—✅唯一可用判据

数据侧的佐证：HumDial 拒识训练集里 TPS 有 1,210 条，SDO 为 0 条，测试集 SDO 仅 200 条 [已核]（v2 定稿 §2.2.2）。这不是疏忽而是构造难度——SDO 与真实指令在声纹、音区、文本上全部同形，只能靠语用线索分辨。公开集无法直接拿来测 S1，必须自建。

另一条反直觉证据：FDB v1.5 里 Gemini 在「对旁人说」场景 99% 保持话轮（Resume 0.99），但在「背景语音」场景却有 70% 误响应（Respond 0.70）[已核]。同一能力换个场景就崩——所以本文坚持分场景、分迷惑度报数，不接受单一「sideTalk 准确率」。

1.3 工作定义

S1 语义拒识 = 在流式音频上，判定「当前话语与正在进行的设备对话框架是否发生断裂」，并据此选择不发起响应 / 继续听 / 仅作上下文保留的动作。

关键词是断裂，不是「非指令」。这个措辞决定了三件事：

  1. 模型必须是条件模型 p(addressee | 音频, 对话状态)，不是无条件的句子分类器；
  2. 判据的主体是 B 层（语用连贯），A 层（词汇）只是辅助；
  3. 判定是可撤销的：断裂可能在句中才显现，也可能被后续证据否定。

1.4 与相邻概念的边界

概念归属与 S1 的边界
语义 VAD / backchannel独立模块（≤1B）管时机（话轮结束、附和点、停顿）；本文管对象。两者并发，见 §2.7
声纹目标说话人锁定独立模块（C6）管「是不是机主」；S1 里机主身份恒为真，该模块对 S1 无判别力
音区 / DoA独立模块管「从哪来」；朝向偏离 ≠ 受话对象是旁人，只作弱先验
self-talk（自语）单列无指定受话人（Duplex-MPE 的 N3）；不并入 S0–S4 产品模块，也不进 S1 分母（v2 定稿 §1.3）
唤醒词硬规则唤醒词命中即 S0，语义层不得否决（与已有文档 §5 一致）

S4 媒体人声独立检测器含指令式台词，作为对抗反例集（不进 S1 分母）
DDSD / SDO学术任务名DDSD 是二分类（是否对设备说）；SDO 是交互行为级，本文的 S1 对齐 SDO

1.5 摘要：十条结论

  1. S1 的本质是检测「与当前设备对话框架的断裂」，不是检测「这句话不是指令」。 [设计]
  2. 声纹、音区、能量、文本关键词在 S1 同时失效，只有带对话状态的语用语义可用 [已核]。
  3. 模型必须条件化：主路径音频直入 + 对话状态缓存（state tokens / KV 复用），而不是退回 ASR 文本 [设计]。
  4. 双头齐报：addressee（L2）与 actionability（L3）两维，单阈值/单分类必被「像指令却说给旁人」击穿 [设计]。
  5. 流式可撤销：逐 chunk posterior + 累积证据 + 迟滞 + 水印点 + EOT flush；证据翻转要能撤销已准备的响应 [设计]。
  6. 动作分级把「误执行 = 0」从口号变成架构约束：低置信只走可逆动作，不可逆动作必须 EOT + 双头高置信 [设计]。
  7. 与语义 VAD 严格并发分工、水印融合，不串行（C3）[设计]。
  8. 最易漏的失败模式是拒识惯性：拒掉 S1 后用户回到设备，系统仍静默 → FRR 飙升；必须显式做重新寻址检测并计入 FRR [设计]。
  9. 评测集主体必须放在「高迷惑 + 最小对」，否则模型靠关键词就能刷到 95%+；同形样本占比须公开 [设计]（与已有文档 §6.2「≥30%」一致）。
  10. 指标沿用 v2 §7.1 五项齐报，另加三条流式增量（最小对一致率 / 撤销正确率 / 恢复率）[设计]。

2.2 输入：音频主路径 + 对话状态缓存

2.2.1 为什么「不等最终 ASR」与「深层语用」不矛盾

这是本方案最容易被质疑的一点，需要讲透：

  • 约束 C1/C2 说的是「不等 ASR 结果」，不是「不用语义」。语义可以来自两个地方：① 音频编码器自身的隐状态（omni 模型把声学+语言信息一起编码）；② 一个持续更新的对话状态缓存。
  • 真正需要「内容」的是 B 层（话题断裂、共同基础），而它依赖的主要是上一轮上下文，不是当前这句话的完整转写。上一轮的上下文在到达当前 chunk 之前早就可用，可以预先编码成 state tokens 常驻 KV cache。
  • 当前这句话的语义，由音频编码器以增量方式逐 chunk 给出隐状态表示，双头只需在这个表示上做轻量分类/打分——不需要生成文本，也不需要等 EOT。
  • 因此：主链路全程无 ASR 依赖；若系统里本来就有流式 partial hypothesis，可把它作为可选辅助条件（late fusion 的一个特征），但绝不允许成为阻塞依赖，且必须在消融里单独验证「去掉它性能掉多少」。

与之对照，已有文档 §3.1 把 partial ASR 文本（≤300ms 内首个可用片段） 作为整个链路的入口。这在级联架构里成立，但在 C1/C2 下不成立。附录 C 给出逐项对照。

2.2.2 对话状态缓存的字段

字段内容更新时机
task_frame当前未完成任务及其待填槽位（如 nav_active / destination=?）每轮 EOT
last_addressee上一轮受话人判定（device / person / self / broadcast）每轮 EOT
sys_stateidle / speaking / just_stopped / recovering事件驱动

工程纪律：状态必须 KV 复用、增量更新，每个 chunk 不得全窗重算，否则计算量随窗口长度线性增长，300ms SLO 无法维持（v2 定稿 §4 已核算过全窗重算与缓存复用的代价差异）。

2.3.1 复用已有文档的 E1–E8 证据体系

S1语义拒识设计与用例覆盖.md §2 给出的八类证据，可直接作为 A/B 层的可操作化特征清单（在音频直入路线里由证据头预测，或从 partial hypothesis 上抽取）：

证据内容归入强度
E1 称呼/第二人称指称人名、亲属称谓（非唤醒词）A强
E2 人—人动作谓词递/拿/收/抱/喂/哄A中—强
E3 设备动作谓词播放/音量/导航/闹钟A中—强（反向）
E4 话语衔接承接系统上一句、补槽位B强（指向设备）
E5 指代与省略「它/这个」+ 前文实物B弱—中
E6 言语行为转述/引用/抱怨/复述B中（转述强指人）
E7 互动标记呼唤—应答对、称呼后停顿A强
E8 话题与任务状态槽位待填、话题延续C弱先验

三条组合规律（可直接作规则基线或证据头的监督信号，来自该文档 §2）：

  • E1 + E2 → 高置信 S1
  • E3 + E4 → 高置信 S0
  • E6（转述）+ E3 → 仍是 S1（「他说把灯关了」不是让我关灯）——最容易翻车的一类
  • 只有 E5 或只有 E8 → 不得定案

注意：这些证据在原文档里是从文本抽取的。在音频直入路线中，它们要么由证据头从隐状态预测（多任务辅助损失），要么从可选的 partial hypothesis 抽取。不能把「有没有 E1」当成唯一判据——真实 S1 里大量样本没有称呼（S1c 自语、S1e 商量后下令），这正是 B 层必须存在的原因。

reject = P(addressee ≠ device) > θ_a
       AND actionability < θ_b
       AND 累积证据通过迟滞（连续 K 个 chunk 稳定）
  • 两个 θ 按场景分别标定（车舱 / 家居 / 眼镜分布不同，v2 §7.5 已强调阈值不能全局共用）[设计]。
  • 两维齐报是防刷分的关键：只训一个「是否指令」的二分类，必然被高迷惑样本击穿，也必然靠关键词偷分。
  • 输出必须带证据 JSON（沿用已有文档 §3.4 的纪律）：{"scene":"S1","p_addressee":0.11,"p_action":0.08,"evidence":["E1","E6"],"rule":"stream_v3"}。

2.5 流式决策状态机

S1 的判据常出现在句中或后半句（「导航去…（转头）你带充电线没？」），单点决策必错。状态机：

状态：LISTEN → HOLD_SUSPECT → PREPARE_RESPONSE → COMMIT / REVOKE
      └─ SILENT（可逆）──────────────────────────┘

逐 chunk t：
  1. 编码音频 chunk_t，复用状态 KV
  2. 双头出 posterior_t，累积证据 E_t = α·E_{t-1} + (1-α)·posterior_t
  3. 迟滞判定：
       E_t 进入 reject 区且连续 K 个 chunk 稳定 → HOLD_SUSPECT（下发「静默/继续听」）
       E_t 进入 accept 区且连续 K 个 chunk 稳定 → PREPARE_RESPONSE（仅准备，不执行）
       两者之间 → 保持当前状态，不下发新动作
  4. 水印点：与语义 VAD 的附和/端点水印对齐，做一次中期融合（不阻塞）
  5. EOT（由语义 VAD 给出）→ flush：
       reject 稳定且 actionability 低 → SILENT / silent_record
       accept 稳定且 actionability 高 且动作可逆性检查通过 → COMMIT
       证据在句末翻转 → REVOKE：撤销已准备的响应，回到 SILENT
  6. 任何时刻命中唤醒词 → 硬规则置位 S0，立即退出 SILENT

三个必须实现的性质：

性质原因不实现的后果
累积 + 迟滞单点 posterior 抖动大一句话内反复切换状态，用户听到「半句回复」
可撤销称呼/转述标记常在句中偏后已经开口才发现是说给旁人
中间态只走可逆动作见 §2.6不可逆误执行

2.6 动作分级与不可逆保护

动作空间（与 v2 §7.5 的 CoDeTT 四动作可映射）：

动作可逆性触发条件代价
silent可逆低置信默认可能漏响应（FRR）
silent_record可逆判定 S1 但需保留上下文无
backchannel可逆由语义 VAD 决定，非 sideTalk 职责无
clarify可逆两解且代价高啰嗦（目标 ≤2%）
prepare_response可逆双头 accept 但未 EOT无
respond部分不可逆EOT + 双头高置信误响应
execute_tool不可逆EOT + 双头高置信 + 动作可逆性检查误执行，一票否决

架构保证：把「误执行 = 0」写进 gate——不可逆动作必须同时满足 EOT、双头高置信、动作可逆性白名单，三个条件缺一不可。低置信一律降级到可逆动作。这比「训练时加惩罚」可靠得多，因为它是结构性约束而非统计性约束。

2.7 与语义 VAD 的并发分工（C3）

模块回答输出时间轴
语义 VAD（≤1B）该不该现在说：话轮结束、附和点、停顿、抢话eot / backchannel_point / pause / 水印逐 chunk，独立流
sideTalk（≤7B，本文）这句话归不归我：受话人、可行动性addressee / actionability / turn_state逐 chunk，独立流
融合 gate最终动作§2.6 的动作水印对齐点 + EOT

接口契约 [设计]：

  1. 两流共享 chunk_id 与 t_ms，各自异步产出，不互相等待；
  2. 只在水印点（VAD 给出的附和/端点候选时刻）做一次中期融合；
  3. 最终融合在 VAD 的 EOT 事件上触发 flush；
  4. VAD 不负责对象判定，sideTalk 不负责时机判定——越界即产生「该沉默却回答」或「该答却被静默」；
  5. 冲突时优先级：唤醒词硬规则 > EOT flush > 双头 posterior > 水印中期预判。

2.8 拒识惯性与重新寻址检测（最易漏）

拒掉 S1 之后，用户常会回到设备：

「…（对副驾）你带充电线没？…（转回）行了，还是导航去机场」

若系统仍停在 SILENT，就是 FRR，而且是最伤体验的一类：用户会觉得「它突然聋了」。

恢复状态机 [设计]：

SILENT 状态下逐 chunk 检测重新寻址信号：
  R1 唤醒词命中                      → 立即 S0（硬规则）
  R2 话题回到 task_frame 域          → 提升 P(device)
  R3 出现设备谓词 + 无 E1/E6 指向人  → 提升 P(device)
  R4 与系统上一句形成承接（E4）      → 提升 P(device)
  R5 silence_run_ms 超过阈值         → 逐步降低迟滞 K（更快响应）
任一组合越过 accept 阈值 → 退出 SILENT，进入 PREPARE_RESPONSE

评测必须包含「静默后恢复」用例，并把恢复失败计入 FRR 的独立切片（§4.5）。只报总体 FRR 会把这类失败淹没在大量正常 S0 里。

2.9 时延预算拆解（C4）

300ms 是每次流式判断的预算，不是端到端首响：

环节预算 [设计]说明
音频 chunk 累积 + 编码器前向40–60ms20–40ms 帧
状态 KV 复用（禁止全窗重算）≤20ms见 §2.2.2
双头 + 证据头推理（≤7B 增量）120–160ms只出 posterior，不生成文本
累积证据 / 迟滞 / 水印融合≤10ms纯逻辑
融合 gate + 动作下发≤20ms
云侧网络与调度余量40–60ms
合计≤300ms每个 chunk 持续给出

注意区分：最终判决在 EOT flush，可能跨越多个 chunk；但「静默 / 不执行」这个中间决策必须在 300ms 内持续给出——这正是 C4 的含义，也是流式架构相对「等整句再判」的价值。v2 §7.1 的 P50 ≤390ms 是静默决策延迟的对外口径，与 C4 是同一时间轴上的两个刻度。

3.1 七类 S1 子场景

编号子场景主判据典型样例期望动作难度

同形样本总占比 ≥30% 是已有文档 §6.2 的硬要求，本文沿用并加严：高迷惑 + 最小对合计 ≥65%。理由：如果随机采样真人语句，模型靠「有没有导航/空调关键词」就能刷到 95%+，而真实翻车全在那些「像指令却是说给别人听」的样本上。

学术侧的同构证据是 ECHO 的 pair accuracy——论文全名 Same Words, Different Actions: Paired Turn-Taking Evaluation under Rewritten Dialogue Contexts，ECHO 是基准名而非标题 [已核]（v2 定稿 §2.2）。一对成员同时判对才得分，专门堵「固定动作策略」刷分。

指标分母目标 [设计]说明
同形子集拒识率全同形子集≥92%语义层唯一有意义的成绩；全集数字会被易样本拉高
语义精确 / 召回判静默样本 / S1 语义正例≥90% / ≥95%低精确会吞真指令
clarify 率全部事件≤2%高了用户嫌啰嗦
pair accuracy最小对总数≥90%两条都判对才计分（ECHO 口径）[已核]

C. 流式增量（本文新增，必须报）：

指标定义目标 [设计]为什么必须有
最早正确判定时点从事件起点到首次给出正确且稳定决策的时延，报 P50/P90越早越好，且不晚于 EOT静态分类评测完全测不到
撤销正确率发生证据翻转时正确撤销且最终判对的比例≥95%检验 §2.5 的可撤销机制

恢复 FRR未恢复的 S0 数 / 拒识后回归 S0 事件数≤2%总体 FRR 会淹没这类失败

4.6 消融四组（证明语义层真的有用）

沿用已有文档 §7.1 的思路，改成音频直入路线的配置：

组配置目的
A仅音频声学编码，无状态缓存、无语义头下限：证明只靠声学在同形集上必然失败
B音频 + 双头，无对话状态缓存隔离出「状态」的贡献
CB + state tokens / KV 复用（目标配置）与 B 的差值 = 语用条件的价值
DC + 动作分级 + 撤销 + 恢复状态机证明可逆降级降低误执行与恢复失败

判读规则：必须分开报「全集拒识率」与「同形子集拒识率」。若 C 相对 B 在同形集上没有提升，说明状态没被用上（先查状态注入实现，别急着换模型）；若 D 相对 C 没有降低误执行，说明 gate 约束没生效。

4.7 泄漏自检

复用已有文档 §7.3 四条，加音频侧三条：

#检查判据
1词表泄漏LR / n-gram 基线 F1 > 0.85 即说明「看到某个词就判」，同形样本不足
2称呼泄漏S1 集称呼词占比 vs S0 集；真实场景也会说「小X，妈让你关灯」

6房间/通道泄漏S1 与 S0 不同房间或不同麦 → 统一采集条件
7DOA 泄漏模型把空间朝向当主判据 → AP2 对照集检验

4.8 防刷分与报告模板

沿用 v2 §7.4 三件套：always-mute / always-respond 双基线差值、配对反事实、cost-weighted 汇总（误响应与漏响应代价不对称，按场景标定权重，不等权平均）。

每份评测报告必须包含：

  1. 各子场景（S1a–S1g）拒识率 + Wilson CI，禁止只报总体；
  2. 同形子集拒识率、高迷惑样本占比、最小对 pair accuracy；
  3. FRR（含恢复 FRR 切片）、误执行次数、静默决策延迟 P50/P90；
  4. 消融四组数字齐全；
  5. 泄漏自检七项全绿；
  6. 每条数据的分母、场景标签（S0–S4）、系统状态、绝对值与相对值并报。

产业侧对照提醒：厂商自报的数字几乎全是相对值或零数值（v2 §3、§5 已核），不可横向比较。自建评测集的价值就在于「同时给出分场景拒识率 + 真指令漏检率 + 误执行 + 时延」——没有任何公开基准同时给这四项 [已核]（v2 摘要第 12 条）。

4.9 与评测工装的映射

沿用 v2 §7.3 的 tools/score.py 现状：分场景拒识率（含 Wilson CI）、FAR/FRR、误执行、clarify 已实现；静默决策延迟、silence preservation、PRR/BIR、SMR/SE、FA/hour 待补。本文新增三项流式增量的实现依赖：

增量指标依赖优先级

撤销正确率逐 chunk 决策日志中
