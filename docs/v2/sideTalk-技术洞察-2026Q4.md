## 0. 摘要：十二条结论

1. **sideTalk 不是新问题，是 25 年前就有名字的老问题换了个马甲。** 2001 年 EUROSPEECH 的 **Off-Talk**（与 on-talk 二分）已明确定义"说话人对第三方或自己、非指向计算机系统的语音"`[二手]`；2025-2026 年它以 side talk / talking to others / side-talk rejection / non-addressed speech 等近义词重新出现，**至今没有统一定义**。

2. **建议的上位术语是 `non-addressed speech`（非指向语音）**，`sideTalk` 作为产品别名保留。理由：它不预设说话人身份（主用户/旁人/电子源皆可），只描述"语用上不指向本设备"这一决定性属性。

3. **定义已经分成四层，混报必然失真**：L1 声学（谁在说、从哪说）→ L2 对象（是不是对设备说）→ L3 动作（该不该动）→ L4 记忆与隐私（知道但该不该说/记）。**sideTalk 落在 L2，但验收必须看 L3/L4。**

4. **学术定义经历四个世代**：addressee recognition（他在对谁说）→ DDSD（是否对设备说，二分类 + EER）→ addressedness / side-talk rejection（该不该动，动作级）→ selective hearing（知道但不能说，隐私级）。每一代都在补上一代缺的那个维度。

5. **学术指标已收敛出"三件套"**：行为分类（Respond / Resume / Uncertain / Unknown）＋ 沉默保持类（silence preservation / side-talk rejection accuracy）＋ 时延对（stop latency / response latency）。人类话轮交接基线约 **200ms**`[已核]`，而 FDB v1.5 实测系统重叠后重入延迟 **1.16–2.76s**，慢 5–6 倍`[已核]`。

6. **2026 年真正的增量是"原因"和"隐私"两个维度**：CoDeTT 的 **SMR** 揭示"动作对但理由错（蒙对）"，MiniCPM-o-4.5 在 Maintain / Stop & Listen 上 SMR **>40%**`[已核]`；SH-Bench 的 **SE** 用调和平均把"为了隐私装聋"这条作弊路径堵住。

7. **最强的一条反直觉证据：同一种能力，换个声学场景就崩。** FDB v1.5 中 Gemini 在"对旁人说"场景 99% 保持话轮（Resume 0.99），但在"背景语音"场景却有 **70% 误响应**（Respond 0.70）`[已核]`。任何"sideTalk 准确率 97%"的单点宣传，第一句要问的是"哪个场景"。

8. **SDO（主用户转头对旁人说话）是全领域数据最稀缺的一类。** HumDial 拒识训练集中，TPS 有 **1,210 条**、SDO 为 **0 条**；测试集 SDO 仅 **200 条**`[已核]`。这不是疏忽，而是构造难度：SDO 与真实指令在声纹、音区、文本上全部同形，只能靠语用线索分辨。

9. **"会打断"与"会分辨受话人"是两种能力，且现有架构无法联合优化。** HumDial 榜单上冠军系统 Int 79.3 / Rej 72.2，Badcat Int 89.7 但 Rej 仅 57.8，**所有系统 Rej 都显著低于 Int**`[已核]`；官方结论即"区分有效话轮与背景语音仍是首要瓶颈"。

10. **产业界已规模化落地，但没有一家公布可比的绝对指标。** 字节 Seeduplex 公开成绩全部是相对自家上一代（误回复/误打断减半、抢话 −40%、判停 −250ms、打断响应 −300ms、判停 MOS +8%、流畅度 MOS +12%、通话满意度 +8.34%）`[已核]`；京东 JoyAI-Talker 给出 0.17 / 0.01 的误触发数字，但**分母未公开**`[未核]`；国际平台层（OpenAI / Google / AWS / LiveKit / Vapi / Retell）**完全不公布**误打断率数值。

11. **机制上收敛为两条路线**：声学层拒绝（多麦阵、波束、DDSD 检测器、音区锁定）与语义层选择参与（状态机、全双工预测器、语义判停/打断）。端到端原生全双工模型正把判定内化进主模型，但**代价是首响延迟不可控**（StepAudio 3 在第三方榜单实测 8.83s 首响`[二手]`），这也是"级联 + 调好的轮次检测"至今仍在榜单上占优的原因。

12. **评测体系存在代差，缺口比想象中大**：学术已有场景化、可复现的基准族；现行国标/团标（TAF）只覆盖唤醒态"误唤醒率"，**全双工态没有对应条目**`[二手]`；没有任何公开基准采用 `FA/hour` 这类工作点口径，也没有任何公开集同时给出"分场景拒识率 + 真指令漏检率 + 误执行 + 时延"四项——**这正是自建评测集的价值位置**。

## 1. 定义：sideTalk 到底是什么

### 1.1 工作定义

**全双工（full-duplex）语音交互**：系统在说话的同时持续聆听，双方语音流可以重叠，无需轮流占用信道。

**sideTalk / 非指向语音（non-addressed speech）**：

> 在全双工会话中，声学上进入设备拾音范围、但**语用上不指向该设备**的人声。典型三类：(a) 正在对话的用户转头对第三人说话；(b) 旁观者之间的对话；(c) 媒体/电子人声（电视、外放、导航）。
>
> 系统的理想行为不是"丢弃"，而是**按当前状态选择一个动作**：不发起响应 / 保持并恢复原话轮 / 停止播报 / 仅作为上下文保留（不写入任务状态）/ 在多用户策略下正常响应。

三个关键词决定了所有后续设计：

- **意图受话者**（intended addressee）：不是"谁在说话"，而是"这句话说给谁听"。同一句话在声纹上完全一致，受话者不同则动作相反。
- **当前交互状态**：系统 `idle` 时拒识 = "不开始"；系统 `speaking` 时拒识 = "是否停/是否恢复"。**同一个场景，状态不同，正确答案不同**——这是 CoDeTT 把 Side-talk 同时放进 Maintain 与 Dismiss 两类动作的原因`[已核]`。
- **授权与设备边界**：同一说话人、同一句话，在已授权/未授权设备、不同音区上，应有不同动作。

| 2010s–2020s | **addressee detection / recognition** | Microsoft、多方对话社区 | 这一轮的预期接收者是谁（可含 gaze）`[已核]` |

### 1.3 十二种叫法的定义原文

同一现象在不同社区有十二种叫法，**每一种的判定层级不同**，这是跨文献比较出错的第一大来源。

| # | 术语 | 出处 | 定义原文（或忠实转述） | 判定层级 |
|---|---|---|---|---|
| 1 | side-talk / side speech | MMW（arXiv:2507.05609） | "interference from side speech"——附近他人语音或重叠谈话，被视为**干扰**而非对话行为`[已核]` | ASR 级（降 WER） |
| 2 | Side-Talk Rejection | WearVox（arXiv:2601.02391） | 五任务之一：识别非设备指向语音并输出 `[Mute]`；子任务 1,082 条 = 582 side talk + 500 有效请求`[已核]` | 任务/动作级 |
| 3 | Third-party Speech (TPS) | HumDial Challenge | 背景说话人在用户提问前后插话，系统应拒识并只响应目标用户`[已核]` | 交互行为级 |
| 4 | Speech Directed at Others (SDO) | HumDial Challenge | 用户临时转向他人（常为无关话题），系统应检测并忽略`[已核]` | 交互行为级 |
| 5 | talking to others | Full-Duplex-Bench v1.5 | 四重叠场景之一："the user briefly addresses someone else"`[已核]` | 交互行为级 |
| 6 | background speech | Full-Duplex-Bench v1.5 | 不同说话人音色、无关话题、远场/低通/带回声，系统应继续原任务`[已核]` | 交互行为级 |

| 8 | addressee recognition | 多方对话经典线 | 给定 utterance 预测受话人；只有约 **20%（80/322）** 的轮次存在显式受话人`[已核]` | utterance 分类级 |
| 9 | selective responding / 选择性参与 | Duplex-MPE（arXiv:2609.31948） | 旁听每位参与者、单独决定是否开口；N1 提及/N2 对他人/N3 自言自语均须沉默`[已核]` | 交互策略级 |

### 1.4 四个世代：定义如何一步步逼近真相

| 世代 | 问题形式 | 输出 | 代表指标 | 盲点 |
|---|---|---|---|---|
| ① 受话人识别（2004–） | 他在对谁说 | 人（A/B/C/O） | 准确率 | 不含设备、不含动作 |
| ② DDSD（2018–） | 是否对设备说 | 二分类 | **EER** | 不含动作、无场景区分 |
| ③ 动作级 addressedness（2025–2026） | 该不该动 | 动作（silence / tool / answer / yield） | 分场景准确率、静默率、pair accuracy | 不含原因、不含隐私 |
| ④ Selective hearing（2026） | 知道，但该不该说 | 答案 + 拒答 | **SE**（四维调和平均） | 不测实时时延 |

这个演进有一个统一的方向：**从"感知判断"走向"策略决策"，再走向"信息治理"**。评测对象也从"模型听没听出来"变成"系统做没做对、有没有付代价"。

### 1.5 四层问题结构与五层评测栈

**四层问题结构**（判断任何一家定义、任何一个指标时，先问它停在哪一层）：

| 层 | 问题 | 判定对象 | 代表工作 | 典型指标 |
|---|---|---|---|---|
| **L1 声学层** | 谁在说、从哪说 | 说话人 / 方向 / 距离 | WearVox、MMW、Multi-Channel Differential ASR | rejection acc、WER |
| **L2 对象层** | 这句话是不是对设备说的 | 受话人 | DDSD、HumDial TPS/SDO、VGBench side-talk | EER、分场景拒识率 |
| **L3 动作层** | 该不该响应、该不该动 | 动作 | CoDeTT、FDB v1.5、Duplex-MPE | silence rate、pair accuracy |
| **L4 记忆/隐私层** | 知道，但该不该记住/说出 | 状态写入 / 披露 | SH-Bench、DuplexLedger | SE、memory contamination |

> **结构判断：sideTalk 落在 L2，但验收必须看 L3/L4。** 判对"没对我说"只是第一步；判完之后动作必须是 silent（或 silent_record），否则 L2 满分也等于失败。

**五层评测栈**（工程实现时按层排布，避免把不同层的指标混在一个看板里）：

1. **信号层**：VAD、AEC、波束成形、多麦空间线索（DoA/IPD/ILD）
2. **门控层**：device-directed 二分类 → FAR / FRR / EER / FA-hour
3. **行为层**：Respond / Resume / Stop / Silence → 行为比例 + 双时延
4. **动作层**：Mute / Tool / Answer → 动作准确率、误执行率
5. **体验层**：恢复播报、上下文保持、答案正确率、3 轮后任务成功率

### 1.6 边界：八个必须排除的邻近概念

| 概念 | 与 sideTalk 的区别 | 一句话判据 |
|---|---|---|
| barge-in / interruption | 争夺话轮，且指向当前说话方 | "speaks over others, violating their turn"；目标动作 **Yield** |
| backchannel（附和） | 不夺权，但指向当前说话方 | "signal attention but do not claim the floor"；目标动作 **Keep** |
| pause（停顿） | 话轮未结束 | 应等待，不得抢话 |
| ambient / background speech | 共享声学通道但非对话参与方（电视、广播、远处旁人） | 与 sideTalk 常被合并，但**处理策略不同**：媒体是持续源，可用场景先验压制；旁人是随机源 |
| self-talk（自言自语） | 无指定受话人（Duplex-MPE 的 N3） | 应按场景单列，**不并入 S0–S4 产品模块** |
| false trigger / 误唤醒 | sideTalk 拒识失败的下游后果 | 唤醒词时代叫误唤醒，全双工时代叫误回复 |
| sidetone（侧音） | 耳机里用户**自己**声音的回放 | 电信术语，仅词形相近，与 sideTalk 无关 |
| Google Duplex | 外呼任务型 agent | 非全双工旁白问题，概念辨析必备 |

### 1.7 判定的四个要素

任何一次 sideTalk 判定，本质是四个要素的联合推断：

1. **谁在说**：说话人身份 / 声纹（是否注册用户）
2. **从哪说**：近场/远场、方向、多通道空间线索（多麦是当前最确定的增益，见 §2.2.3）
3. **对谁说**：语义指向、称呼、指代、对话结构（S1 的核心证据）
4. **想干什么**：是否寻求话轮（turn / continue / backchannel / barge-in / aside）

> **洞察**：sideTalk 本质是**语用问题**，不是声学问题。但 2025-2026 年最强的工程增益恰恰来自声学侧（多通道 +8.3pt），说明当前系统的语用推理还很弱——这既是差距，也是机会。

### 1.8 三个正交轴与两处高频误用

**轴一：说话人身份 × 指向对象**（决定难度）

```
                指向设备            指向他人            无明确指向
主用户        S0 该响应          S1 (SDO) 最难        self-talk
旁人          （越权/多用户）     S3 (B2) 较易         —
电子源        S4 媒体人声         —                    —
```

**轴二：判定层级**——L1 声学 / L2 对象 / L3 动作 / L4 记忆（见 §1.5）。

**轴三：闭集 vs 开集**——公开基准多是闭集（S0–S4 已知），真实场景是开集（新的旁白形式、新的媒体源）。**开集是拒识问题的本质**，这一点在 §2.5 再展开。

**两处高频误用**：

1. **把 "off-talk rate" 当"旁白发生率"**。在 ECHO 里它是模型在 off-talk 条件上的**错误率**（越低越好），不是场景占比`[已核]`。
2. **把可穿戴的 side-talk rejection 与全双工 sideTalk 混为一谈**。前者是 ASR 前端的声学拒绝（主体是旁观者），后者是对话策略的语义选择参与（主体常是用户本人）`[已核]`。两者的指标（WER vs 行为分类）不可互换。

## 2. 学术界：定义如何被操作化，指标如何被计算

### 2.1 演进总表

| 阶段 | 时间 | 核心问题 | 代表基准/工作 | 标志性指标 |
|---|---|---|---|---|
| ① 受话人识别 | 2004– | 他在对谁说 | addressee benchmarks（2025 版：1,666 轮、仅 20% 显式受话人） | accuracy |
| ② 设备指向检测 | 2018– | 是否对设备说 | Amazon DDSD、Adaptive KD | EER、FRR@FAR |
| ③ 全双工重叠处理 | 2025–2026 | 重叠时该响应/等待/停止 | FDB v1→v1.5→v2、FD-Bench、EchoChain | 行为五分类 + 双时延 |
| ④ 动作级 addressedness | 2025–2026 | 该不该动 | WearVox、VGBench、HumDial | 分场景拒识率、switch mute |
| ⑤ 多方选择性参与 | 2026 | 多人场景何时该说/该沉默 | Duplex-MPE、MSI-Bench、DuplexLedger、ECHO | silence preservation、pair accuracy |
| ⑥ 原因与隐私 | 2026 | 为什么对、该不该说 | CoDeTT、SH-Bench | SMR、SE |

**一个诚实的方法论提醒**：这六个阶段不是替代关系，而是**叠加关系**。今天做产品，L2（对象）和 L3（动作）必须同时具备；只做 L2 会在"动作选错"上翻车，只做 L3 会在"对象判错"上翻车。

### 2.2 基准逐项

统一模板：**定位 → 规模与构造 → 指标 → 关键数字 → 局限**。所有数字均标注信度。

#### 2.2.1 全双工行为基准

**① Full-Duplex-Bench v1.5（arXiv:2507.23159，ICASSP 2026，NTU/CMU/Meta 系）** `[已核]`

- **定位**：目前"重叠行为"评测的事实标准，首个全自动基准。四个场景：user interruption / user backchannel / talking to others / background speech。
- **规模**：v4 正文明确 **200 / 99 / 100 / 100 条，合计 499 条**（注意：不是"每场景 200 条"，这是本轮修掉的一处传播错误）。
- **构造**：同一用户音色对第三人说话（talking to others：−8dB、4kHz 高频衰减、45/120ms 混响）；不同音色 + 无关话题（background speech：−15dB、3kHz 低通、带回声）。
- **指标**：① 行为五分类（由 GPT-4o 读 parakeet-tdt 的转写与词级时间戳判定）；② stop latency / response latency；③ 韵律适应（pitch、intensity、WPM、UTMOSv2，配对 t 检验）。
- **关键数字（talking to others，Respond / Resume）**：

| 模型 | Respond | Resume | stop \| response 延迟（s） |
|---|---|---|---|
| Gemini | 0.00 | **0.99** | 1.69 \| 1.78 |
| Nova Sonic | 0.10 | 0.90 | 1.77 \| 2.04 |
| Freeze-Omni | 0.58 | 0.25 | 1.39 \| 1.32 |
| Moshi | 0.20 | 0.19 | 0.87 \| 2.38 |
| GPT-4o Realtime | **0.91** | 0.02 | **0.18** \| 1.16 |

- **背景语音（Respond / Resume）**：Gemini 0.70 / 0.30；Sonic 0.01 / 0.98；GPT-4o 0.93 / 0.04；Freeze 0.63 / 0.25。
- **两种策略**：repair-first（GPT-4o：秒停，但不分对象）vs continuity-first（Gemini/Sonic：分对象，但反应慢 1.7s）。
- **局限**：英语；受控合成混音；每场景 99–200 条，置信区间宽度约 ±7–10pt。

**② Full-Duplex-Bench v1（arXiv:2503.04721）/ v2（arXiv:2510.07838）** `[摘要]`

- v1 是 pause / backchannel / turn-taking / interruption 四行为的自动化评测前代框架；v2 扩展到多轮与工具调用。**逐场景指标（如 Takeover Rate）本轮未核**，不做数值引用。

**③ FD-Bench（arXiv:2507.19040，Interspeech 2025）** `[摘要]`

- LLM + TTS + ASR 的全双工评测流水线，关注打断、延迟、鲁棒性。**指标名与数值本轮未核。**

**④ EchoChain（arXiv:2604.16456）** `[已核]`

- **定位**：打断后的**状态更新推理**，不是"该不该停"，而是"打断后还记不记得原来在干什么"。
- **规模**：200 段被打断的对话，四个系统（GPT-realtime-2025-08-28、Gemini Live 2.5 Flash native audio、Grok Voice Agent、+1）。
- **指标**：MPR（mean pass rate，整段对话全部 rubric 通过才算过）、MCP（mean criterion passed，单项通过比例）。
- **关键数字**：**没有任何系统 MPR 超过 50%**；MPR 全部低于 50%。
- **失败分类学（可直接复用为诊断标签）**：contextual inertia（拿到新信息仍按原计划生成）、interruption amnesia（忘记被打断前的内容）、objective displacement（目标漂移）。

**⑤ People Making Conversation（arXiv:2610.12802）** `[已核]`

- **定位**：用真人对话的"停顿点/话轮终点"反测系统的自然度。
- **规模**：176 段无脚本对话（Seamless Interaction），标注 **427 个停顿点 + 482 个话轮终点**。
- **关键数字**：基于静音的端点器延迟约 **1–4s**，基于语义的轮次检测约 **8s**——"在该停的时候停"这件事，工业级系统普遍差一个数量级。

#### 2.2.2 拒识与受话人基准（与 S0–S4 最直接相关）

**⑥ HumDial Challenge / HumDial-FDBench（arXiv:2601.05564，ICASSP 2026）** `[已核]`

- **定位**：唯一带 TPS + SDO 双标注的大规模**真人表演**基准；拒识赛道把"该拒的语音"分成四类：URB（用户实时附和）/ PH（停顿）/ TPS（第三方说话）/ SDO（对别人说话）。
- **规模（逐格核对，这是本文最关键的一张表）**：

| 分片 | Int（FQ/ND/RR/TS/ST） | Rej（URB/PH/TPS/SDO） | 合计 |
|---|---|---|---|
| Train | 1507/1211/1213/1213/1212 | **1211/1211/1210/0** | 9,418 |
| Dev | 200×5 | 200/200/200/200 | 1,800 |
| Test | 600×5 | 600/600/600/**200** | 5,000 |

- **SDO 训练样本 = 0**，TPS 训练样本 = **1,210**（此前流传的"120 条"是截断错误，本轮已纠正）。
- **指标**：`Final = 0.4·S_Int + 0.4·S_Rej + 0.2·S_Delay`，其中 S_Delay 是相对 60 分基线的延迟分。
- **榜单（Top-3 + 反例）**：Cookie_asr **Int 79.3 / Rej 72.2** / 1.260s / Final 76.6；Badcat Int **89.7** / Rej 57.8；SenseDialog 76.4 / 60.9。100+ 团队注册、15 个有效提交。
- **官方结论**：**所有系统的 Rej 都显著低于 Int**，区分真实用户话轮与背景语音仍是全双工首要瓶颈。
- **局限**：SDO 测试仅 200 条（±7pt）；综合分不可拆解；无"误执行"项。

**⑦ VGBench（arXiv:2609.32536）** `[已核]`

- **定位**：把 sideTalk 从"是不是对我说的"推进到"**agentic addressedness**"——统一动作空间 `{silence, tool call, answer}`。
- **规模**：1,018 条 = **395 side-talk + 223 self-talk + 400 speaker-switch 配对**。
- **关键数字**：六个裸 Audio LLM 的最高 switch mute 率仅 **14%**（免训练最好 6%）；VoxGate 监督训练后 **91.3%**；side-talk 准确率 68.4% → 70.9%，self-talk 静默 52.0% → 60.0%，WearVox 总体 72.14% → 76.30%。
- **核心洞察**：**"能认出该调哪个工具，却几乎不肯闭嘴"**——感知能力与抑制能力是两件事。
- **局限**：数据未公开；英语；规模偏小。

**⑧ Reject or Not?（arXiv:2512.10257，美的 + 哈工程）** `[已核]`

- **定位**：首个中文智能家居拒识基准，11,913 条人工标注的文本-语音对。
- **类别数的正确口径**（本轮消歧）：**摘要说"twelve typical dialogue types"（含有效指令作为对照类），正文说"covers 13 categories of invalid queries"（剔除有效指令后的无效类）**。两者不矛盾，引用时必须写清"12 类对话类型 / 13 类无效查询"。
- **方法**：三层协同——Qwen-2.5-3B adapter（学语义边界）+ 家庭级历史对话模块（个性化）+ 家庭级 RAG（记住并修正历史误拒）。
- **局限**：文本为主，不含"对谁说"的声学判定。

**⑨ DDSD 工业线（Amazon / Apple）** `[摘要]`

- Amazon Interspeech 2019：1st-turn 324K / 2nd-turn 13K，主指标 **EER**；按对话类型分输出分支相对降 EER 12.5%，attention pooling 相对降 4.97%（此两项为**二手转述**，本轮未核原文）。
- Adaptive KD（arXiv:2508.02801）：知识蒸馏 + 自适应，用于设备指向检测的轻量化。
- 价值：**口径稳定可复现**（EER、FRR@FAR），是产业界唯一"敢报绝对数"的一层。

**⑩ 受话人识别基准（arXiv:2501.16643）** `[已核]`

- 1,666 轮多方对话，只有 **20%（80/322）** 的轮次显式指定受话人；GPT-4o 做受话人识别"仅略高于随机"`[已核]`。
- 意义：证明"对象判定"是独立难题，不能寄望 ASR 之后的文本模型顺手解决。

#### 2.2.3 可穿戴与 ASR 前端（声学拒绝线）

**⑪ WearVox（arXiv:2601.02391，Meta + CMU）** `[已核]`

- **规模**：3,842 段第一视角多通道眼镜录音，五个任务；Side-Talk Rejection 子任务 **1,082 条 = 582 side talk + 500 有效请求**（有效请求由工具调用任务复制构成配对）。
- **关键数字**：**单通道 85.6% → 多通道 93.9%**（+8.3pt）；总体准确率 61.9% → 66.4%。
- **洞察**：**空间信息本身就是 sideTalk 信号**，不必等语义模型。这条是全领域最确定的工程杠杆。

**⑫ MMW（arXiv:2507.05609，Meta）** `[已核]`

- **定义**：side speech = 附近他人语音或重叠谈话，被视为**干扰**（ASR 视角），不是对话行为。
- **结构**：Tri-Mamba 的 Mix Block 在**原始波形层**融合多通道（保相位）+ Frame Diarization Mamba 层做帧级抑制 + 多尺度 GRPO 联合优化帧级/句级抑制。
- **结果**：噪声条件下 **WER 相对降低 4.95%**（摘要原文）。此前流传的"67.81%→3.71%"是误引，已删除。
- **局限**：指标是 WER，**与轮次行为级拒识不可比**。

**⑬ Multi-Channel Differential ASR（arXiv:2509.14430，Meta + OSU）** `[已核]`

- beamformer + 麦克风选择 + **轻量流式 side-talk 检测（STD）**，不建模说话人身份；相对 WER 最多降 **18.0%**。

#### 2.2.4 多方选择参与

**⑭ Duplex-MPE（arXiv:2609.31948）** `[已核]`

- **规模**：2,000 场景 × 显式/隐式称呼 = **4,000 段对话，110.93 小时**；3–4 名说话人 + 1 助手；8 个开源语音系统。
- **标签**：T（直接请求）/ N1（提及但不请求）/ N2（对他人或他物）/ N3（无指定受话人）/ N4（人类自行解决后应停）。N1/N2/N3 均要求沉默。
- **四计分**：fresh-onset response rate、answer accuracy、**silence preservation**、answering-window yield。
- **关键数字（显式称呼下 silence preservation）**：MiniCPM-o 4.5 **0.9267** > Voila > FLM-Audio > Moshi > **Freeze-Omni 0.0000**；PersonaPlex 仅 **840 / 20,360** 个应沉默窗口保住沉默（0.0413）。Voila 有 76 个窗口未获 judge 标签，若计为通过仅 +0.37pp。
- **方法学警示（两处必须修正的旧数据）**：
  - 两个指标的排名 Spearman 相关为 **0.5206**（不是 −0.4303）；**8 个模型中 6 个在显式/隐式下换位**——指标选择会改变排名。
  - 文本参考（Gemini 3.1 Pro）对显式/隐式称呼的响应率差 **64.3 个百分点**，而语音模型无显著差异——**"会沉默"可能只是"普遍不响应"**。

**⑮ MSI-Bench（arXiv:2609.24812，Amazon）** `[已核]`

- **规模**：1,152 条，中英各 576；12 个模型 × 15 种配置。
- **指标**：**BIR**（bystander interference robustness：被打断后原答案仍通过 rubric 的比例）、**PRR**（premature response rate：未被指代就抢答的比例）。
- **关键数字**：Gemini 3.1 Pro BIR 78.0 / PRR 19.8；GPT Realtime 2.1 (xhigh) BIR 73.7 / PRR 9.4。
- **洞察**：把评价从"分类准不准"推进到"任务有没有被旁白破坏"，与 Amazon 的 DDSD 传统合流。

**⑯ DuplexLedger（arXiv:2610.27581）** `[已核]`

- **规模**：1,094 段持久会话，14,681 个事件；四类事件 Write / Update / Ignore / Retain，**Ignore 类占 51.4%**（旁白语音不得写入任务状态）。
- **价值**：抓到"隐性污染"——旁白没被响应，但被记住了，后续答非所问。
- **注意**：此前流传的"1.2 秒观测窗"本轮**未在正文核到**，已降级不引用。

**⑰ ECHO（arXiv:2609.17360）** `[已核]`

- **引用注意**：论文标题是 *Same Words, Different Actions: Paired Turn-Taking Evaluation under Rewritten Dialogue Contexts*，**ECHO 是基准名而非标题**。此前把它写成"ECHO: A Matched-Contrast Benchmark..."是错误的引法。
- **设计**：同一段重叠转写 + 两种前置上下文，一个要求 Yield、一个要求 Keep；另含 off-talk 样本诊断"不必要的让权"。
- **指标**：**pair accuracy**——一对成员同时判对才得分，杜绝"固定动作策略"刷分。
- **关键数字**：四个系统中有三个严重 over-yielding，**正确保持话轮的 backchannel 不足 13%**，成对成功率 ≤4%。

#### 2.2.5 诊断与联合分（2026 年最重要的方法论增量）

**⑱ CoDeTT（arXiv:2603.25434）** `[已核]`

- **规模**：**18,000 条决策实例 / 300+ 小时中英双语**；4 个动作（Maintain / Stop & Listen / Takeover / Dismiss）× 14 类意图，且区分系统状态（SystemSpeaking / SystemIdle）。
- **关键设计**：Side-talk 同时出现在 Maintain（系统在说话时）与 Dismiss（系统空闲时）两个动作下——**同一场景、不同系统状态，期望动作不同**。
- **SMR（Semantic Misalignment Rate）**：动作判对但意图判错的比例，`SMR_M = #{动作=M 且 意图错} / #{动作=M}`。
- **关键数字**：**MiniCPM-o-4.5 在 Maintain 与 Stop & Listen 上 SMR 常年 >40%**，即"蒙对"。
- **意义**：**拒识准确率可以被"声学直觉"刷出来**，必须同时报 SMR。

**⑲ SH-Bench（arXiv:2512.06380，ACL 2026）** `[已核]`

- **规模**：**3,968 段多说话人混合音频（157.5 小时、285 位说话人）+ 77.36k 道五选一题**（含固定选项 "I don't know"）。
- **两种模式**：general（都答对）/ selective（旁观者相关问题必须答"不知道"）。
- **SE（Selective Efficacy）**：四个准确率（主说话人/旁观者 × general/selective）的**调和平均**，任一维度差即拉低总分。
- **关键数字**：Gemini 2.5 Pro 97.3 / 97.0 / 65.5 / 59.2 → **SE 75.8**；GPT-4o-audio 72.3 / 84.4 / 43.2 / 44.5 → **SE 56.1**；Step-Audio-2-mini + BPFT 97.4 / 94.3 / 81.0 / 96.1 → **SE 91.7**。
- **洞察**："听懂"和"该不该说"是两个可独立测量的维度；调和平均堵住了"为隐私装聋"的作弊路径。

**⑳ FLEXI（arXiv:2509.22243）** `[已核]`

- 六个真人-LLM 交互场景（含紧急情况下的模型主动打断）；六个指标：TOR（takeover rate）、TTR（turn-taking rate）、TSS（topic shift score）、EDS（emergency detection score）、JIR（jump-in rate）、JSD（backchannel 分布与参考分布的 Jensen-Shannon 散度）。
- 价值：把"打断"从单一准确率拆成"该不该插、插得及不及时、插完有没有跑题"。

**㉑ HiPLEX（arXiv:2610.07727）** `[摘要]`

- 层级策略分解（Hierarchical Policy Factorization），目标是降低"不该接管时接管"；在停顿/附和机会上的 takeover rate 下降。

### 2.3 指标词典（按决策链分层，共 23 个）

**A. 决策层（说还是不说）**

| 指标 | 定义 | 分母 | 出处 |
|---|---|---|---|
| Rejection accuracy | 应静默样本中被正确静默的比例 | 应静默样本 | HumDial |
| Side-Talk Rejection accuracy | 侧聊片段被判为"非指向设备"的比例 | 侧聊片段 | WearVox |
| switch mute rate | 同词换声源后正确静音的比例 | speaker-switch 对 | VGBench |
| **PRR**（premature response rate） | 尚未被指代就响应 | 应静默样本 | MSI-Bench |
| **BIR**（bystander interference robustness） | 被打断后原答案仍通过 rubric | 被打断样本 | MSI-Bench |
| FAR / FRR / EER | 二分类的误接受/误拒绝/等错误率 | 全体 | DDSD 线 |

**B. 行为层（沉默得自然吗、恢复得干净吗）**

| 指标 | 定义 | 出处 |
|---|---|---|
| **silence preservation** | 应沉默窗口内"无语音或仅不夺话轮的短确认"的比例 | Duplex-MPE |

| answering-window yield | 该让出回答窗口时让出 | Duplex-MPE |

**C. 任务层（有没有把 sideTalk 污染进任务）**

| 指标 | 定义 | 出处 |
|---|---|---|

### 2.5 方法学争论与已知陷阱

1. **术语与指标名不收敛，跨基准数值不可直接比较**。FDB 的 Resume 0.99 与 Duplex-MPE 的 silence preservation 0.9267 分母完全不同（前者是"行为占比"，后者是"应沉默窗口保住沉默的比例"）。
2. **单一聚合指标掩盖行为**。Duplex-MPE 实测：两个指标的排名 Spearman 仅 0.5206，**8 个模型中 6 个换位**。
3. **"沉默"可以被刷**。允许 always-mute，rejection accuracy 就能接近满分——所以 2026 年的新基准普遍用配对指标 + 正控制 + 联合分。
4. **"会沉默"≠"听懂了"**。64.3pp 的显隐差距出现在文本模型上，语音模型全体不显著——沉默可能只是迟钝。
5. **行动惯性是主要失败模式**，不是"听不见"。VGBench 里模型工具识别率很高，却不肯静音（最高 switch mute 14%）；Step-Audio-R1.1 是典型"选对工具但照做"。
6. **过度沉默是另一条退化路径**。模型可以学会"闭嘴"，但学不会"分辨"；必须成对报告（S1 拒识率 vs S0 漏检率）。
7. **半双工模型"不可评"还是"不公平"**。Duplex-MPE 以协议不兼容为由拒绝评测半双工系统，导致工程界最关心的"半双工 + 调优 VAD 到底差多少"没有公开答案。
8. **LLM-as-judge 的可靠性**。ECHO/FDB 都用 GPT-4o 判定行为，人工抽检比例未公开；Duplex-MPE 报告 judge 一致率 99/100、98/100。
9. **数据构念错误**：训练集若只有"目标 + 干扰"的混合、没有"目标与干扰同时说话"，模型会学到"sidetalk ≈ 静音"，上线后一旦主副驾同时说话就整段丢。这是最常见的构念错误。

### 2.6 机制五流派（sideTalk 在哪里被处理）

| 流派 | 代表 | 机制 | sideTalk 的处理位置 | 局限 |
|---|---|---|---|---|
| ① 双流并行隐式学习 | Moshi、OmniFlatten、LSLM | 用户声道 + 自身声道同时建模 | 无显式判定，靠数据分布 | Unknown 高达 0.59 |
| ② 显式状态机 | neural FSM、SALMONN-omni、Freeze-Omni、VITA-1.5 | listening/thinking/speaking 状态转移 | 状态规则 + 背景守卫 | 阈值硬编码，易误杀 backchannel |
| ③ 全双工预测模块 | MinMo Full Duplex Predictor | LLM 语义决策"继续说/停/轮次" | 面向轮次而非受话人 | 仍需与受话人判定协同 |
| ④ VAP 轮次预测 | VAP、三方 VAP、MuVAP | 自监督预测未来语音活动 | 天然容纳多方重叠 | 只做活动预测，需级联 LLM |
| ⑤ DDSD/addressee 级联 | Amazon 系、SAS | VAD 后接二分类器 | **显式处理**：非指向则静默 | 级联延迟与错误传播 |

> **2026 年的新动向**：sideTalk 开始进入**训练数据合成**（Harness、DuplexDrama），把旁白变成可编程的"意图事件"；同时端到端模型把判定内化进主模型，但首响延迟与可解释性成为新的代价。

## 3. 产业界：能力已经落地，指标几乎不公开

### 3.1 四条路线

产业界不用统一定义，按产品形态分成四条路线，各自的 KPI 完全不同：

| 路线 | 代表 | sideTalk 的定义 | 核心指标 | 现状 |
|---|---|---|---|---|
| ① 穿戴/眼镜 | Meta（WearVox/MMW）、Rokid、雷鸟 | 附近他人语音/重叠谈话，是**对佩戴者识别的干扰** | rejection acc、WER | 声学问题优先，功耗不允许跑重型语用模型 |
| ② 语音助手/多说话人 | Amazon Alexa、小度、小艺 | device-directed vs 背景语音 | EER、FAR/FRR、误唤醒率 | 硬件层口径成熟，全双工态缺失 |
| ③ 实时语音 API / 平台 | OpenAI、Google、AWS、ElevenLabs、LiveKit、Vapi、Retell、Deepgram | **无 sideTalk 概念**，拆成 VAD / endpointing / interruption handling | false interruption、P95 延迟 | **平台层完全黑箱** |

### 3.6 评测体系的代差

- **TAF 团体标准**（TAF-WG7-AS0043）：只定义唤醒态"误唤醒率"。**sideTalk 发生在免唤醒/全双工态，现行标准没有对应条目**`[二手]`。
- **中国信通院（CAICT）**：本轮检索范围内**未见**语音全双工/抗干扰专项（空结论，存在漏检可能）`[二手]`。

- **商业测试公司已先行**：Roark/Evalgent 把"背景对话导致 derail""mm-hm 类附和误停""抢话"列为全双工必测失效面`[二手]`。

## 4. 学术界 vs 产业界：对照总表

### 4.1 七维对照

| 维度 | 学术界 | 产业界（国际） | 产业界（国内） |
|---|---|---|---|
| 术语 | off-talk / talking to others / side-talk rejection / non-addressed speech | background speech / DDSD / interruption sensitivity | 抗干扰 / 拒识 / 抢话 / 误打断 / 语义拒识；**不用 sidetalk** |

| 主体假设 | 两种并存：旁观者（可穿戴）与对话用户本人（全双工） | 主要是对话用户 + 环境人声 | 主对话用户 + 旁人闲聊/其他音区 |

| 评测方法 | 场景化基准 + LLM judge + 人工抽检 | 文档化配置 + 定性故障树 | 大规模 A/B + 人工 MOS |

| 最大缺口 | 真实多人重叠数据、跨基准不可比、半双工不可评 | 误打断率无公开基准 | 无第三方专项、口径不透明 |

### 4.2 同一模型跨基准不可比的举证

| 模型 | FDB（对旁人说） | FDB（背景语音） | HumDial | 说明 |
|---|---|---|---|---|
| Gemini Live | Resume 0.99 | **Respond 0.70** | 未参赛 | 同能力、不同声学场景，差 70 点 |
| GPT-4o Realtime | Respond 0.91 | Respond 0.93 | 未参赛 | 对象判定几乎为零，但时延最好（0.18s） |
| Nova Sonic | Resume 0.90 | Resume 0.98 | 未参赛 | 与 Gemini 相反：背景音更强 |
| JoyAI-Talker | 未测 | 误触发 0.17 | 未参赛 | 分母不明 |

三条不可比的技术原因：**场景不同**（对旁人说 ≠ 背景语音 ≠ 旁人之间 ≠ 电视人声，难度差 30–70 点）、**分母不同**（99–200 条 vs 2,000 条 vs 每秒/每小时）、**判定不同**（LLM judge vs 人工标签 vs 厂商自评）。

### 4.3 六个结构性差异

| 维度 | 学术界 | 产业界 |
|---|---|---|

## 7. 落地建议：把洞察变成可执行的评测与指标

### 7.1 五项齐报（对外口径，建议直接固化）

| 指标 | 分母 | 建议目标 | 为什么必须有 |
|---|---|---|---|
| 分场景拒识率（S1–S4） | 各场景应静默样本 | S1 ≥90% / S2 ≥95% / S3 ≥98% / S4 ≥95%，带 Wilson CI | 单一"sideTalk 准确率"必然掩盖场景差异 |
| **FRR**（真指令被静默） | S0（与访客指令分开） | ≤3%（内部 ≤2%） | 与拒识率成对，缺一即可刷分 |
| **误执行** | 应静默样本 | **0**（不可逆动作）；可逆动作单独计数 | 产品级一票否决，学界几乎不测 |
| 静默决策延迟 | 应静默事件 | P50 ≤390ms | 对齐 FDB 的 stop latency 口径 |
| **FA/hour** | 真实使用时长 | 运营监控 | 唯一能反映"用户真实被打扰"的口径 |

### 7.2 自建评测集：场景矩阵与组量

**至少覆盖七个正交维度**：说话人（主用户/第三方/多人/媒体）、受话对象（助手/旁人/群体/自己/无明确）、距离通道（近场/远场/离轴/电视外放/耳机）、系统状态（idle/speaking/刚停止/恢复中）、语义（请求/陈述/疑问/命令/附和/停顿）、语言（中/英/中英混说）、设备（单麦/多麦/眼镜/车载/音箱）。

**建议组量（下限）**：

| 子集 | 条数 | 关键要求 |
|---|---|---|
| SDO 核心集 | 500–1,000 | 声纹/音区与 S0 完全一致（否则声纹变成泄漏特征） |
| TPS 集 | 500 | 覆盖用户问题前/后插话 |
| Self-talk 集 | 300 | 命令式与非命令式各半（单列，不并入 S1–S4） |
| Media 集 | 300 | 电视/短视频/语音消息/播客，**含指令式台词** |
| Backchannel/Pause 集 | 500 | 必须配"不得新开回答"的判定 |
| Speaker-switch 反事实 | 300 对 | 同词、同上下文，只改来源/距离 |
| 正控集（S0） | 500 | 确保不是 always-mute |
| **隐性指代集** | 200 | 无称呼、靠上下文推断"其实是对我说" |

**协议要点**：实时流式回放（不能离线整段）；idle 与 speaking 分开测；固定工作点（如 FRR ≤2% 或 FA/hour ≤1）；统一 VAD/端点器；记录模型实际音频而非 token 时间戳；每场景 ≥500 条才报 CI。

### 7.3 S0–S4 与评测工装的指标映射

| 学术指标 | 本项目指标 | `tools/score.py` 现状 |
|---|---|---|
| Rejection accuracy | 分场景拒识率（S1–S4） | ✅ 已实现（含 Wilson CI） |
| FAR / FRR | FAR_w / FRR（S0） | ✅ 已实现 |
| 误执行 | 误执行计数（一票否决） | ✅ 已实现 |
| clarify | clarify 率 ≤2% | ✅ 已实现 |
| 静默决策延迟 | P50/P95 静默延迟 | ⚠️ 待补（需事件时间戳） |
| silence preservation | 应沉默窗口保持率 | ⚠️ 待补（需窗口标注） |
| PRR / BIR | 抢答率 / 打断后恢复率 | ⚠️ 待补（需配对清单） |
| SMR | 判对理由错误率 | ⚠️ 待补（需意图标注） |
| SE | 记忆-隐私联合分 | ⚠️ 待补（需隐私探针） |
| **FA/hour** | 每小时误触发 | ⚠️ 待补（需时长归一） |

> **建议**：前四项已在仓库落地，可直接用于第一轮选型；后六项按"静默延迟 → FA/hour → PRR/BIR → SMR/SE"的顺序补，因为前两个只依赖时间戳，成本最低。

### 7.4 防刷分三件套

1. **always-mute / always-respond 双基线**：任何拒识率必须同时报与基线的差值。
2. **配对反事实**：同词换声源、同词换系统状态（CoDeTT 的 Maintain vs Dismiss），杜绝固定动作策略。
3. **cost-weighted 汇总**：误响应（在旁白上回答）与漏响应（该答不答）代价不对称，按场景分别标定权重，不要等权平均。

### 7.5 与技术选型的映射

- **动作空间对齐**：产品的 `respond / silent / silent_record / clarify / NEI` 可直接映射到 CoDeTT 的四动作（Maintain / Stop & Listen / Takeover / Dismiss），便于与公开榜单对照。
- **多通道是免费增益**：WearVox 的 +8.3pt 与差分 ASR 的 −18% WER 都指向同一结论——手机双麦、音箱麦阵要显式做进特征，**不能只靠语义模型**。
- **校准与阈值是两个问题**：VGBench 的"能认出工具却不肯闭嘴"说明输出概率与决策阈值必须分开做；阈值应按场景（车舱/家居/眼镜）分别标定，而不是一个全局值。

## 8. 引用纪律与写作模板

### 8.1 引用时的"四必须"

1. **必须锁版本**：FDB v1.5 的场景名在 v1（side conversation / ambient speech）与新版（talking to others / background speech）之间变过；ECHO 是基准名不是标题。
2. **必须锁场景**：同一模型在"对旁人说"与"背景语音"上可以差 70 点。
3. **必须锁分母**：每场景 99–200 条 vs 2,000 条 vs 每小时，量纲不同。
4. **必须标口径**：相对值/绝对值/自报，三者不可混。

### 8.2 不要写的四句话

- ❌ "某模型 sideTalk 准确率 97%"——没有说明场景与分母。
- ❌ "行业误打断率约 X%"——没有任何公开来源支持这个数。
- ❌ "StepAudio 的 98.9 说明它 sideTalk 最强"——98.9 是四项子集平均，不含 talking_to_others/background_speech 独立项。
- ❌ "Gemini 完全不受旁白干扰"——它在 background speech 上误响应 0.70。

### 8.3 一句话结论

> **sideTalk 的核心矛盾不是"听不出来"，而是"听出来了仍然要做错动作"**——所以评测必须同时测三件事：对象判对了吗（L2）、动作选对了吗（L3）、代价可控吗（L4）。只测第一件的系统，一定会在真实场景里翻车。

## 附录 B：常见失败模式

| 失败模式 | 表现 | 根因 | 对策 |
|---|---|---|---|
| **错误接话**（false accept） | 旁白被当指令执行 | L2 判错；训练集缺同形负样本 | 同形负样本 + 场景先验 |
| **过度沉默**（over-silence） | 真指令也被吞 | 只优化拒识率，未约束 FRR | 五项齐报 + 正控集 |
| **抢话**（premature response） | 用户没说完就开口 | 端点检测太短 / 语义判停缺失 | 双阈值 + 语义判停 |
| **打断失忆** | 被打断后忘了原任务 | 状态未持久化 | 状态账本（DuplexLedger 式探针） |
| **上下文惯性** | 拿到新信息仍按原计划说 | 状态更新失败 | 显式状态 token + 重规划 |
| **目标漂移** | 说着说着换了话题 | 长上下文漂移 | 目标锚点复述 |
| **固定动作策略** | 永远沉默或永远响应也能得分 | 指标未配对 | pair accuracy / 双基线 |
| **蒙对** | 动作对但理由错 | 声学直觉替代语义 | SMR 诊断 |
| **声纹泄漏** | S1 与 S0 的说话人分布不同，模型靠声纹偷分 | 数据构念错误 | S1/S0 同音色同房间 |
| **词表捷径** | 学到"灯=设备词、递=旁人词" | 负样本不同形 | 同句跨设备配对（同一句话在不同能力档案下标签不同） |
| **媒体误触发** | 电视里带疑问语调的对白被响应 | 媒体与真人声学相似 | 媒体参考信号 + 场景状态先验 |
| **自激** | 自己的 TTS 被自己响应 | AEC 残留 | 参考信号 + 硬否决窗口 |
