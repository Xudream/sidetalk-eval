00 / Executive Summary

核心结论 · 十条

  1. side talk 不是新问题，是 25 年前就有名字的老问题的新马甲。2001 年 Oppermann 等在 EUROSPEECH 提出 Off-Talk（与 on-talk 二分）——"说话人对第三方或自己的、非指向计算机系统的语音"；2025-2026 全双工浪潮中它以 side talk / side conversation / talking to others / off-talk / side-talk rejection 等近义词重现，至今没有统一定义。
  2. 学术界已把 side talk 做成可评测对象，四大锚点：Full-Duplex-Bench v1.5 的 talking to others 场景、Duplex-MPE 的 N1/N2/N3 沉默标签与 silence preservation、ECHO 的 off-talk 条件与 pair accuracy、DuplexLedger 的 dedicated side-talk stage。
  3. 同一个词横跨两个问题域。可穿戴/ASR 社区的 side talk 主体是旁观者（声学层拒绝）；全双工对话社区的 side talk 主体是对话用户本人（对话策略层：不接话、不让权、不打断主线）。引用文献必须先问"主体是谁"。
  4. 学术指标已收敛出"三件套"：行为分类（Respond/Resume/…，LLM-as-judge）＋ 沉默保持（silence preservation / side-talk rejection）＋ 时延对（stop/response latency）；辅以韵律适应与人类基线（约 200ms）。
  5. 产业界几乎不用 "side talk" 一词。国际口径：background speech / device-directed speech (DDSD) / interruption sensitivity；国内口径：抗干扰、无关对话、抢话、误打断、误回复、动态判停。对字节/火山/达摩院 6 个官方页面全文正则检索，sidetalk|side talk|旁白|侧说话 0 命中。
  6. 国内已形成自有指标体系：Seeduplex（2026-04）宣称复杂场景误回复率/误打断率相对半双工减半、抢话比例 -40%、判停延迟 -250ms、打断响应延迟 -300ms、判停 MOS +8%、流畅度 MOS +12%、A/B 满意度 +8.34%——全部为相对自家上一代的相对值，跨厂商不可比。
  7. 机制收敛为两条路线：声学层拒绝（去噪/VAD/DDSD 级联/多音区锁定）与语义层选择参与（状态机、Full Duplex Predictor、语义打断、VAP 轮次预测）；端到端原生全双工正把判定内化进主模型。
  8. 拦截强度 vs 响应速度的权衡被官方文档反复承认：Vapi"slightly delay the detection of speech onset"；阿里云百炼"开启语义判停与拒识后可能导致对话延迟增加"；学术侧总结为 repair-first vs continuity-first。
  9. 评测成熟度存在代差：学术已有自动化可复现场景基准族并出现方法学自省；产业公开指标只有硬件唤醒层 FAR/FRR（成熟）与大厂相对值宣称（不可比），国际平台层黑箱，国内第三方评测无专项。
  10. "会沉默"≠"听懂了不该接"。Duplex-MPE 显示文本模型对名字线索敏感（响应率差 64.3pp），五个语音模型全部不显著（最小 p=0.2365）——旁白拒绝得好可能只是"普遍不响应"的副产品；必须配应答正确率一起读。
01 / Concept

概念界定 · 什么是 side talk

全双工语音交互中，声学上进入拾音范围、语用上不指向系统的人声，就是 side talk。它必须与插话、反馈语、背景语音严格区分——这三个邻居恰好对应系统三种不同的正确动作。

工作定义

全双工（full-duplex）：系统在说话的同时持续聆听，双方语音流可重叠，无需轮流占用信道。

Side talk（旁白/旁语）：典型三类——(a) 对话中的用户转头对第三人说话；(b) 旁观者之间的对话；(c) 用户自言自语/思考出声。系统理想行为：不响应、不让权、不遗忘主线，事后平滑接回。

1.3概念边界（最容易写错的部分）

概念与 side talk 的区别一句话判据
barge-in / interruption（插话）争夺话轮，指向当前说话方v1.5："speaks over others, violating their turn to speak"；ECHO 目标动作 Yield
backchannel（反馈语/附和）不夺权，但指向当前说话方v1.5："signal attention but do not claim the floor"；ECHO 目标动作 Keep
ambient / background speech共享声学通道但非对话参与方（电视、广播、远处旁人）v1.5："shares the acoustic channel but is not directed at the system"
side talk（旁白）对话参与方（用户或在场者）说出、但指向第三方/自己v1.5："the user briefly addresses someone else"
false trigger（误触发）side talk 拒绝失败的下游后果唤醒词时代=误唤醒；全双工时代=误回复
sidetone（侧音）耳机/电话里用户自己声音的回放，与 side talk 无关电信术语，仅词形相近
Google Duplex外呼任务型 agent，非全双工旁白问题概念辨析必备

两处高频误用：① 把 "off-talk rate" 当"旁白发生率"——ECHO 里它是模型在 off-talk 条件上的错误率（低=好）；② 把可穿戴 side-talk rejection 与全双工 side talk 混为一谈——前者是 ASR 前端声学拒绝，后者是对话策略的语义选择参与。

02 / Academia · Definitions & Mechanisms

学术界洞察（一） · 定义操作化与机制流派

2.1定义操作化的四个基准锚点

Full-Duplex-Bench v1.5 把重叠语音拆成四类可控事件（user interruption / user backchannel / talking to others / background speech），每个 trial 用 4 要素参数化（上文查询、重叠时机、重叠内容、说话人身份与声学通道），以重叠结束时刻切分 pre/post-overlap 行为窗。Duplex-MPE 把"何时开口/沉默/停止"变成标签问题——T（对助手的直接请求）、N1（提及未请求）、N2（对他人/他物）、N3（无受话人含自言自语）、N4（应答后须停）。ECHO 用成对改写设计：同一重叠转写、两种前置上下文（一个要求 Yield、一个要求 Keep），pair accuracy 对成对成员同时判对才给分，杜绝固定动作策略刷分。DuplexLedger 把 side-talk 事件嵌入持久记忆协议（1.2 秒观测窗），考察"该忽略的没忽略"是否污染记忆。

3.5方法学争论（批判视角）

  1. 术语不统一、指标名不收敛，跨基准数值不可直接比较（Resume 0.99 与 silence preservation 0.9242 分母完全不同）。
  2. 单一聚合指标掩盖行为——Spearman −0.4303 实证"指标选择改排名"。
  3. 合成数据 vs 真实录音之争（可控性 vs 真实感；HumDial/WearVox 补位）。
  4. 半双工模型"不可评"还是"不公平"？Duplex-MPE 拒绝评半双工（协议不兼容），意味着无法回答"半双工+VAD 方案在旁白场景差多少"。
  5. LLM-as-judge 依赖人工抽检兜底（Duplex-MPE 报 99/100、98/100 一致率）。
  6. "拒绝得好"存在歧义：可能是受话人推断，也可能是普遍迟钝。
  7. Jefferson/Goffman 是思想先祖而非术语出处——2025-2026 全双工文献并未回溯引用。
04 / Industry · Global

产业界洞察（一） · 国际

国际产业界官方文档不使用 "side talk"。最接近的官方概念：Amazon 的 device-directed speech、平台层的 background speech、OpenAI 的 turn detection / interruption handling。side talk 被拆解进四级流水线。

4.1四级流水线

层职能代表实现
①前端降噪 / 回声消除ElevenLabs WebRTC · Vapi 双去噪器 · LiveKit voice isolation · Amazon implicit AEC
②VAD / 语音起点各平台 VAD 阈值、min_interruption_duration 类参数
③端点 / 轮次判定OpenAI server_vad / semantic_vad（eagerness）· Pipecat Smart Turn · Hume 韵律 end-of-turn
④打断执行策略cancel-and-regenerate · pause-and-resume（LiveKit：嘈杂线路多为"假打断"）· preemptive generation

4.2指标：硬件层成熟，平台层黑箱

成熟的一层（硬件唤醒）：Amazon Science 论文实锤 DDSD 评测口径——"We use false reject rate (FRR) and false accept rate (FAR) as our metrics and report FRR at two fixed FAR values (non-playback and playback)"（区分设备自外放与不放声两种条件）。黑箱的一层（模型/平台）：OpenAI / Google / AWS / ElevenLabs / Vapi / Retell / LiveKit / Pipecat / Hume 的公开文档均未公布误打断率、误触发率数值或基准集；只有定性故障树（Retell："agent 抢话 → endpointing 太短"）与第三方小样本测量博客。任何"行业误打断率 X%"的数据都应视为不可信。

4.3三组已核实的工程张力

  1. 防误打断 vs 响应速度：Vapi 官方承认防背景打断阈值 "even if it slightly delays the detection of speech onset"。
  2. 预生成 vs 浪费算力：LiveKit preemptive generation "doesn't always reduce latency"。
  3. 降噪过度 vs 保真：Retell 社区投诉降噪连真实第二说话人一起消掉（2026-02 社区帖，二手）。

6.2评测体系现状

  • TAF 团体标准只覆盖唤醒态"误唤醒率"——side talk 发生在免唤醒/全双工态，现行标准没有对应条目。
  • 中国信通院（CAICT）：本次检索范围内未见语音全双工/抗干扰专项（检索空结论，存在漏检可能）。
  • SuperCLUE 实时语音基准（2024-12）：4 维度 15 项能力，含全双工/打断专项未核实；当时评测综述把"全双工对话评测"列为未来展望。
  • 商业测试公司已先行：Roark / Evalgent 把"背景对话导致 derail""mm-hm 类附和误停""抢话"列为全双工必测失效面（2026-09，二手）。
  • 在线指标：可确认的官方口径只有阿里云百炼——"语义判停与拒识"产品开关，目标是"避免误打断、误唤醒"，并承认"开启后可能导致对话延迟增加"。

结论：产品走到了标准与评测前面。全双工把 side talk 问题放大而非解决——半双工+唤醒词天然挡住旁白；全双工免唤醒后系统"一直在听"，忽略旁白从外围工程变成核心能力，而公开评测体系尚未跟上。

09 / Guidance

对技术洞察报告的写作建议 · 八条

  1. 先给术语映射表，再引用任何数字——把 off-talk / side conversation / talking to others / side-talk rejection / 抗干扰 / 抢话 / 拒绝反应对齐到一张表。
  2. 标注基准与版本——FDB v1.5 场景名在 v1（side conversation / ambient speech）与新版（talking to others / background speech）间有演化。
  3. 不跨基准比数字——v1.5 与 Duplex-MPE 分母/量纲不同；指标选择已实证改变排名。
  4. 分两条线叙述机制——"声学层拒绝（旁观者）"与"语义层选择参与（对话主体）"是两个问题域。
  5. 产业数字全部注明口径——国内宣称均为相对自家上一代；"行业误打断率 X%"类说法一律不可引用。
  6. "会沉默≠听懂了不该接"——引用 silence preservation 时配 answer accuracy 一起读。
  7. 把"评测缺口"作为洞察点——学术基准族 vs 产业黑箱/宣称、标准只覆盖唤醒态、第三方评测无专项的代差，是最有报告价值的发现之一。
  8. 人类基线作前瞻锚——200ms vs 1-3s 差距 + Seeduplex 官方自承"与人人对话仍有不小差距"，可作"离自然交互还有多远"的收尾论据。
